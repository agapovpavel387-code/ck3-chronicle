## Не выпущено

### Титулы / Titles

- Дубли одной смены власти убраны. Сейв пишет одну дату дважды — буквально `768.9.24=7705 768.9.24=7141`, — движок читает последнюю; теперь так же и `tools/save_reader.py`.
- Новый `reconcile()` в `tools/titles.py`: запись без держателя склеивается с записью на ту же дату (только при совпадении действия — `created` не слипается с `inherited`), две записи на одну дату сводятся к одной, ближайшей к событию (память → сейв → дамп). Одиночные записи без держателя остаются: историю не выбрасываем.
- На сейве 917 года: склеено 22 723 записи без имени, сведено 188 сдвоенных дат, осталось 897 одиночных записей без держателя. Смен власти в летописи 1 714 → **1 177**; пар «дата + титул» 478 → **0**; дат с двумя живыми держателями 18 → **0**.
- Летопись: «В 887 году учреждён титул «Дэмбия».» без держателя, «титул прекратил существование», «сменился государь» вместо строки с пустым именем.
- `check_titles.py`: две новые проверки — «нет записи без держателя при известном держателе на ту же дату» и «на одну дату — один держатель». Считаются по id титула, а не по имени: одинаковые названия у разных титулов больше не дают ложных срабатываний. Чекер прогоняет тот же конвейер, что и сборка: склейка, память, сверка.

## 0.3.0-alpha

Титулы стали отдельной моделью: три источника сводятся в одну историю, у каждой смены власти есть причина, у потери — имя титула.

### Титулы / Titles

- Новый `tools/titles.py`: модель титула поверх трёх свидетелей — история в дампе, история в сейве и память персонажа.
- Память читается по титулам: `variables.landed_title`, `variables.reason`, `participants.new_holder`. Раньше эти поля не читались вовсе, поэтому «потерян важный титул» шёл без имени.
- Ключ `Id` (с большой буквы) в памяти теперь понимается наравне с `id`: без этого память о титулах читалась впустую.
- Слияние ищет запись истории в окне десяти дней: память и история совпадают по дате только в трети случаев.
- Причина из памяти нормализуется (`Inherited` → `inheritance`); при расхождении с историей побеждает память, расхождение считается в отчёте.
- Повторы одной записи схлопываются: в самом дампе бывают две одинаковые строки.
- Восстановлены 19 причин смены держателя: `inheritance`, `granted`, `revoked`, `conquest`, `conquest_claim`, `conquest_populist`, `conquest_holy_war`, `created`, `appointment`, `appointment_succession`, `abdication`, `migration`, `faction_demand`, `swear_fealty`, `stepped_down`, `independency`, `usurped`, `leased_out`, `lease_revoked`.

### Хроника / Chronicle

- Смена власти называет причину: «Синин: власть перешла к Пасанг — уступлен по требованию фракции».
- Потеря титула называет титул, причину и нового держателя: «Яньцин лишился титула «Гуаньнэй» — уступлен по требованию фракции».
- Созданный титул читается как учреждение: «В 887 году учреждён титул «Дэмбийя» — его держателем стал Пасанг».
- Мёртвая ветка `title_loss` в разборе строк убрана: второй `case` был недостижим.

## Не выпущено

Причина у событий: войны получают повод и цель, смерти — причину, история титулов перестаёт терять смены власти внутри партии.

### Импорт / Import

- Новый `tools/save_reader.py`: читает текстовый `gamestate` из `.ck3` и достаёт то, чего нет в дампе — `wars.active_wars` с `casus_belli` и целевыми титулами, а также историю титулов в обеих формах записи (карта `дата=держатель` и блоки `дата={ holder=… type=… }`). Есть самопроверка без игры: `--selftest`.
- `build_world.py --extra`: склейка истории по `key` титула и события войн; воспоминание о той же войне уступает версии с поводом.
- `import_save.py` запускает `save_reader.py` сам и передаёт результат в сборку; относительные пути из командной строки больше не ломают запуск экстрактора.
- `tools/check_dump.py`: эталон дампа (`docs/dump-baseline.json`) — падает, если после пересборки экстрактора стало меньше титулов, персонажей или воспоминаний.

### Хроника / Chronicle

- Повод войны — метка перед строкой и цель в тексте: «Началась война с X. Цель — Рей.»
- Имена поводов — из локализации игры (`tools/cb_names.py`), а не из ручного словаря: «Малая священная война», «Покорение герцогства», «Война за объединение Китая». 112 из 118 поводов игры.
- От семейства повода зависит фраза: за веру, за дань, за верховенство, за вольности, за землю, за титул. Роль (напали / на нас / третья сторона) тоже меняет строку.
- Войны берутся не только из идущих: у каждой войны в памяти персонажа есть дата, противник и категория повода (`war_cb`) — это даёт причину и для давно закончившихся войн. На сейве 917 года: 4 155 событий из памяти против 112 идущих.
- Исход: если титул-цель уже сменил держателя — «Добились своего: «Рей» отошёл к ним» или ««Рей» достался другому».
- В итогах года и главы — за что воевали: «войн — 5 (за землю 3, за веру 1)».
- Причина смерти в записи: «Причина — во сне» (2 722 из 2 811 смертей на сейве 917 года).
- Воспоминания: типы на русском и английском, незнакомый тип становится записью вместо потери; заметки чужих людей в летопись не идут.
- Выгрузка в markdown получает повод в квадратных скобках.

## 0.1.0-alpha — 2026-11-05

Первая альфа для Crusader Kings III 1.20.x. / First alpha for Crusader Kings III 1.20.x.

### Приложение / App

- Пять экранов: Род, Мир, Хроника, Свод, Досье; плюс «Своё сохранение» и «Данные».
- **Род** — конспект по слоям: строка на человека, отступ на поколение, сворачивание, поиск с раскрытием пути. Полотно с панорамой — второй режим.
- **Мир** — две линзы: радиус знания и политическая, у политической два слоя — по домам всех держав и земли рода.
- **Хроника** — главы по эпохам, три слоя внутри года (в роду / при дворе / издали), нити войн и распрь, честный счёт пропущенного.
- **Свод** — поколения, ветви, кто чем владеет, авантюристы.
- **Досье** — пакет фактов для рассказчика: линии рода, дома, державы, верования.
- Карточка человека: родство с вами, владения, культура, вера.
- Интерфейс полностью двуязычный: навигация, кнопки, легенды, карточка человека, форма хроники, свод, импорт. Переключатель RU/EN, выбор запоминается; по умолчанию — язык браузера.
- Текст летописи, досье и родства идёт на языке сейва: это цитаты из источника.

### Инструменты / Tools

- `import_save.py` — импорт сохранения в один запуск: дамп → мир → карта. Из панели или из командной строки.
- `serve.js` — локальный сервер с API: список сохранений, статус окружения, импорт с прогрессом, отмена, установка зависимостей.
- `build_world.py` — сборка мира: державы, люди, события, линии рода, карты, таблицы.
- `doctor.py` — диагностика дампа: дома, династии, персонажи, игрок.
- `knowledge_pilot.py` — кэш карты из файлов игры.
- Проверки: `npm test` — 37 + 15 + 14 + 12.
