# Титулы: три свидетеля и одна модель

Титул в сохранении описан не в одном месте, а в трёх. Каждое знает своё, и
вместе они дают то, чего не даёт ни одно по отдельности: **кто** держал титул,
**когда** он сменился и **почему**.

| Свидетель | Что даёт | Чего не знает |
|---|---|---|
| `titles[*].history` в дампе экстрактора | смены держателя до старта партии: дата, держатель, действие | обрывается на дате начала игры |
| `save-extra.json` (`tools/save_reader.py`) | смены по ходу партии из текстового `gamestate` | не знает причины: только факт |
| `memories` с `landed_title` | причину (`reason`), нового держателя (`new_holder`), участников | не у всех титулов есть память |

Работает это так:

```
gamestate.json ─┬─ titles[*].history ─────────┐
                │                             ├─► tools/titles.py ─► мир ─► летопись
save-extra.json ┼─ titles (история сейва) ────┤        │
                └─ memories (landed_title) ───┘        └─► docs/titles-baseline.json
```

| | |
|---|---|
| Титулов в дампе | 19 776 |
| Из них со землёй (империя, королевство, герцогство, графство) | 6 378 |
| Записей истории после склейки и чистки | 40 982 |
| Память о титулах | 9 756 записей, из них 8 379 — получение, 1 377 — потеря |
| Нашла пару в истории | 5 715 (96% от значимых тиров) |
| Добавлено из памяти | 267 |
| Сведено дублей (без держателя и двойных дат) | 22 911 |
| Расхождений причины | 462 |

## Почему нужна склейка, а не один источник

* **История в дампе обрывается** на дате старта партии. Всё, что случилось
  после, есть только в сейве — `tools/save_reader.py` читает `landed_titles`
  прямо из текстового `gamestate`.
* **id в двух источниках разные.** `c_parsberg` — 863 в дампе и 951 в сейве.
  Склейка только по `key` титула, никогда по id.
* **Причина есть только в памяти.** История пишет `Inherited`, `granted`,
  `revoked` — но у памяти ещё и `reason` (`inheritance`, `appointment_succession`,
  `conquest_holy_war`…) и `participants.new_holder`.
* **Даты расходятся.** Память и история указывают один и тот же день только в
  3 092 случаях из 7 138. Ещё 3 775 попадают в окно десяти дней — поэтому
  слияние ищет запись в окне, а не по точному равенству.

## Как разрешается конфликт причины

Память ближе к событию: она помнит участников и повод. История лишь
фиксирует, что держатель сменился. Поэтому при расхождении **побеждает
память**, а расхождение считается в статистике (`conflict`) и видно в отчёте
сборки. На сейве 913 года таких 462 из 5 715 — в основном `Inherited` против
`appointment_succession`.

Формат записи истории после слияния:

```json
["0899-08-29", 16915, "inheritance", "dump+memory"]
```

Дата, держатель, причина (ключ игры), источник. Источник — `dump`, `save`,
`memory` или их сумма через `+`.

## Сведение дублей

Одна и та же смена может прийти из двух мест и записаться дважды:

* **Сейв пишет одну дату дважды.** Буквально: `history={ … 768.9.24=7705 768.9.24=7141 … }` —
  движок читает последнюю, поэтому `tools/save_reader.py` тоже берёт последнюю.
* **Дамп пишет смену без держателя.** Такая строка дублирует запись с именем на ту же дату.
  `reconcile()` переносит на неё источник и причину, а дубль убирает — но только при
  совпадении действия: `created` не склеивается с `inherited`.
* **Одиночная запись без держателя остаётся.** Историю не выбрасываем: летопись скажет
  «сменился государь» без имени.

На сейве 917 года: склеено 22 723 записи без имени, сведено 188 сдвоенных дат,
осталось 897 записей без держателя. Смен власти в летописи стало 1 177 вместо 1 714 —
разница и была дублями.

## Что попадает в летопись

| Вид | Откуда | Фильтр |
|---|---|---|
| `succession` | история титула | империи, королевства, герцогства всегда; графства — только своего рода |
| `title_loss` | память о потере | те же тиры; баронства не идут никогда |

Баронства отсечены не по недосмотру: в памяти их 2 507 записей, и ни одна не
про род. Графства чужих держав — 4 721 запись, тоже шум для семейной хроники.

В году событий бывает больше, чем помещается в слой, и события власти (смена
власти, потеря титула) идут первыми: на сейве 920 года в летопись проходит 27
строк о потере из 113 событий (остальные — молва четвёртого кольца или те же
смены, что уже показаны строками смены власти).

В строке потери теперь есть имя титула, причина и новый держатель:

```
Яньцин лишился титула «Гуаньнэй» — уступлен по требованию фракции.
Гарция потерял «Наварра» — завоёван по притязанию; им стал Абдаллах.
```

## Проверка

```bash
python tools/check_titles.py --dump gamestate.json --extra _cache/save-extra.json
python tools/check_titles.py --world app/_data/world.json
python tools/check_titles.py --dump gamestate.json --baseline docs/titles-baseline.json
python tools/titles.py --selftest
```

`check_titles.py` проверяет: даты на месте и не убывают, одна дата и
держатель — одна запись, нет записи без держателя при известном держателе на ту же дату,
на одну дату — один держатель, держатели существуют среди персонажей, причины
известны игре, вассалитет без циклов, у потери титула есть имя и причина,
одна смена власти не записана дважды, чужие графства не просочились.
С `--baseline` падает, если титулов или записей стало меньше эталона.

`titles.py --selftest` проверяет слияние без дампа и без игры.

## Границы

* **111 записей памяти** ссылаются на титул, которого в дампе уже нет:
  игра его уничтожила. Имени взять неоткуда — такие записи не выдумываются.
* **Завершённых войн игра не хранит.** Причина потери титула из войны
  известна только там, где её записала память.
* **Смены до партии** идут из истории титула без причины: игра её не сохранила.
* **Бинарные сейвы (ironman)** так не читаются: в них нет текстового
  `gamestate`. Импорт работает как раньше, без войн и без дополненной истории.

## Карта титулов

Слой «Титулы» на экране «Мир» показывает все титулы, кроме баронств: империи,
королевства, герцогства и графства. Строится он не на глаз, а по de jure-иерархии:

```
провинция 17263 → c_PHI_cotabato → d_mindanao → k_mindanao → e_majapahit
```

* `_cache/map.json` даёт провинцию баронства (`b_aachen` → 822);
* `titles[].vassals` — баронства графства, графства герцогства и так выше;
* `titles[].de_jure` — прямой сюзерен, он надёжнее обратной сборки.

Покрытие на сейве 917 года: 4 703 графства, 1 314 герцогства, 260 королевств,
88 империй, 11 677 провинций из 13 270 (88%). Остальные 901 провинция — земля
без титула: она есть на карте, но графства у неё нет, и это видно по цвету.

**Заливка** — по графствам, тона бумаги с едва заметным уклоном: карта не должна
спорить с летописью. **Границы** — по смене титула между соседними пикселями:
империя 3 px, королевство 2 px, герцогство и графство по 1 px, но разного цвета.

**Зум** — колесо мыши, перетаскивание, кнопки `+` / `−` / «Сброс», клавиатура
(`+`, `−`, стрелки, `Home`). До 4×; выше — мыло без тайлов.

**Клик** даёт цепочку целиком, а не верхушку:

```
Псков — графство
  герцогство — Новгород · королевство — Новгород · империя — Россия
```

Из панели — переход в хронику по этому титулу: события знают `titleKey`, поэтому
карта и летопись говорят об одном титуле, а не о двух тёзках.

Проверка: `python tools/check_titles.py --titles-map app/_data/titles-map.json`
(имя у каждого графства, цепочка той же длины, провинции покрыты, доля цепочек ≥ 70%).
